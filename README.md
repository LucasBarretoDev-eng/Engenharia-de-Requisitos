
# Engenharia de Requisitos

Bem-vindo(a) ao repositório dedicado aos meus estudos e projetos em **Engenharia de Requisitos**, uma das disciplinas mais críticas e estratégicas da Engenharia de Software.

---

##  O que é a Engenharia de Requisitos?

A Engenharia de Requisitos é a área da Engenharia de Software responsável por **descobrir, analisar, documentar e verificar** as necessidades dos stakeholders (clientes, usuários e a própria equipe de desenvolvimento) em relação a um sistema de software. 

Ela traduz desejos e dores de negócios muitas vezes abstratos em especificações técnicas claras, servindo como uma "ponte" entre o mundo dos negócios e o mundo do desenvolvimento.

### O Processo Principal:
1. **Elicitação:** Descobrir o que o sistema precisa fazer (via entrevistas, workshops, prototipação, etc.).
2. **Análise e Negociação:** Avaliar viabilidade, identificar conflitos e priorizar o que é essencial.
3. **Especificação:** Documentar os requisitos (User Stories, Casos de Uso, RFs e RNFs) de forma inequívoca.
4. **Validação:** Garantir que o que foi documentado é exatamente o que o cliente precisa.
5. **Gestão:** Controlar as mudanças de escopo ao longo do ciclo de vida do projeto.

---

##  Qual o papel na Engenharia de Software?

Se o código é a fundação de um prédio, a Engenharia de Requisitos é a **planta arquitetônica**. Construir um software incrível sem requisitos claros é apenas construir o sistema errado mais rápido.

O seu papel fundamental na Engenharia de Software inclui:

*   **Minimização de Riscos e Custos:** Corrigir um erro de requisito na fase de codificação ou testes pode custar até 100 vezes mais do que corrigi-lo na fase de especificação.
*   **Alinhamento de Expectativas:** Garante que os desenvolvedores, designers e clientes estejam na mesma página, evitando a clássica frustração do *"não era bem isso que eu queria"*.
*   **Definição do Escopo:** Serve como base para estimativas de tempo, custo e alocação de equipe.
*   **Critério de Sucesso:** Um software só tem qualidade se atende aos requisitos definidos. Eles são a base para os planos de testes de QA (Garantia de Qualidade).
